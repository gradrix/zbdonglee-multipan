SiSDK 2026.6.2 multi-PAN RCP for the SONOFF ZBDongle-E (EFR32MG21): Silicon Labs' own sample
(`openthread_app/ot-ncp/cpc/rcp-uart-802154`) with the CPC stale-completion fix
(`patches-2026.6.2/`), the stick settings of the v2024.6.2 manifest, and `DEBUG_EFM`/`DEBUG_EFM_USER`
with a reset-on-assert `assertEFM()` (`firmware-2026.6.2/efmreset.c`).

Without `DEBUG_EFM` every SiSDK 2026.6.2 CPC UART build stayed silent on this chip; with it the
build answers. Why is still open (TODO.md). A failed assert resets the chip, so the host reconnects.

Running on one dongle since 2026-11-11 (it replaced `v2024.6.2-cpcfix.1`). 24-hour soak passed
2026-11-12: no bad frame, no stack restart, no radio tx timeout (the 2024.6.2 build logged about five
a day), 99.9 % of Zigbee probes answered with the same mean latency, Thread devices attached
throughout.

- SiSDK 2026.6.2, CPC secondary 4.9.2, OpenThread RCP 3.1.2.0; no BLE, no CPC security
  (cpcd `disable_encryption: true`)
- UART 460800 baud, no hardware flow control
- Tested host: SiSDK 2026.6.2 packages (cpcd 4.8.0, zigbeed 9.1.1, otbr-agent 3.1.1)

Built by GitHub Actions with `./build-2026.6.2.sh` from this tag; checksums in `SHA256SUMS`. It is
built from the same project inputs as the soak-tested file and differs from it only in embedded name
and path strings.

What it fixes and how to flash it: README.md and docs/root-cause.md.
